# Page development authorization policy

## Default-deny rule
No page may be created, edited, deleted, restyled, rearranged or refactored unless
the user explicitly requests that page-level work.

This includes route/page files and page composition; changes to layout, content,
responsive behavior or visual styling; and replacing or redesigning existing pages.

## Allowed without page authorization
- Repository architecture documentation.
- Dependency and build configuration.
- PDS integration foundation, global tokens and stylesheet wiring.
- Directory ownership documentation.
- Non-visual infrastructure and quality tooling.

## Shared components
Creating or changing Header, Footer, navigation, controls or other shared UI
components also requires an explicit task describing the component scope.

## Before page work
Confirm the exact page, requested change and permitted scope. Do not expand the
task into unrelated visual changes. Preserve existing page design unless the
user explicitly authorizes a redesign.
